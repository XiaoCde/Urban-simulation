## 二、你的四个疑问，实测答案

### 1. 「是不是全程随机穿梭在几万栋楼里，而不是最后到一个地点？」

**先更正一个数量**：`SOLIDS.stats().visible = 21491` 栋可见建筑实体，
你说「几万栋楼」是对的；之前代码注释里的「433 栋」是旧数据。

实测结果比「随机穿梭」更具体，是两个真问题：

| 现象 | 修复前（400 人 / 20h） |
|---|---|
| 室外的人落在楼体 AABB 内部 | 每时刻 6~34 人（1.5~8.5%），全天持续 |
| 没有在办的目标、站在街上 | 12:30 达 **294/400（74%）** |
| 一天节点被放弃 | **1364 / 约 3600（38%）** |
| 一天节点完成 | 1051 |
| 走到目标 9 m 内的人数 | 白天多数时刻只有 16~130 人 |

注意：无目标的人**实际位移很小**（60 人轨迹里 `noGoalPath` 仅 1979 m / 20h），
所以准确的说法不是「全城乱走」，而是「目标一个个被丢掉，人长时间空档站在街上，
看起来谁也没到过任何地点」。真正的随机换链只在 net 模式到链端点时发生。

根因有三条：
- 步行链只在初始化筛过一次，A\* 折线、避险直线兜底、换链都可能把人送进楼；
  写 `obj.position` 时没有建筑 AABB 检查（`COLLIDE_PED` 还显式忽略了 building 标签）。
- `judge()` 里淋湿、疲劳、「今天放弃过几次」被写成**正反馈**，人一不顺就放弃；
  放弃后下一节点可能几小时后才到点，于是长期空档。
- 全城分布下通勤常有 2~3 km，步行 1.4 m/s 在时间窗内根本走不到，超时/放弃集中。

### 2. 汽车避让 / 自由行

| 现象 | 修复前 |
|---|---|
| 车 `t>1`（跑到边的延长线外） | 168 车次 |
| 车位置落在楼体内 | 18 车次 |
| `dir` 翻转（含 U-turn） | 1627 次 / 41 个采样间隔 |
| 斑马线探测 `pedNear>0` | 144 次，**100% 只发生在被认领的车** |
| 背景车礼让行人 | **0 次** |

`traffic.js` 里 `if (car.owner !== null && pedProbe)` 让 96 辆车里只有少数被
居民认领的会查行人，其余背景车直接穿过斑马线上的人 —— 这是你说「避让没生效」
的直接原因。另外 `car.t` 恒增但 `head` 对反向车写成了 `1-t`，导致 dir=-1 的
停止线、让行、跟车、入口占用判定方向全部反过来；红灯判定用 `car.wait < 3.2`
且 `car.wait` 从不在 claim/release 里清零，等过阈值就会**永久绕过红灯**。
`pickNext` 里 `void back` 把算好的来路丢掉，28% 概率在路口随机选边、死路原地掉头，
就是「自由行」的来源。认领时还会把车硬瞬移到首边中点 `t=0.5`，实测最远从
**3096 m** 外闪现。

### 3. 走路姿态

- `play()` 只在状态切换时调用，决策层 slow/hurry/resume 改了步速后，clip 的
  `timeScale` 仍停在旧值 —— 「人加快了，腿还是原来的频率」。
- 掉头时 `p.dir` 立刻翻转但 `yaw` 靠 `dt*6.5` 平滑插值，实测上万人帧
  「位移方向与朝向相反」（倒着走）。
- 静止但没有 idle clip 的模型会兜底返回 `walk`，存在「原地走」。

### 4. 时间轴连续性

**倍率本身没问题**：×1 / ×24 下 `CLOCK.minute`、`FLOOD.tMin`、
`LIVE.simSec` 的比值都精确是 **24.00**，人和水同层。

真问题在拖动瞬间：`catchUp` 用 `dt = sec/n`（最大 20 仿真秒）补跑，一步跨
28 m，帧末「moved>2 隐藏保护」把全城人一次性收起；同时给决策时钟灌进
**120 秒虚假经历**，`holdT=231 / route=104 / liveClipT` 等执行层状态跨时刻残留。
另外 `flood.tMin` 只在每渲染帧末更新，子步里人和水差一帧；
`?capture=1` 的定时器还会在离线验收的两个 evaluate 之间偷偷插帧。

> 澄清：基线里 `hidden=400` **不是人消失**，是 360 m 距离裁剪（相机在默认位置，
> 400 人分散全城都在视野外）。专项复核把相机贴到人群后，seek 前后可见人数
> 31 → 300 → 31，后一个 31 是正常的距离裁剪。这一条之前被我误判过，已更正。

## 五、仍然存在的边界，如实说明

1. **认领瞬间仍有 ≤1200 m 的一次投放跳跃**。彻底消除需要新增「车沿路网开到
   出发地接人、人在原地等」的接驾阶段，本轮没做（会牵动驾驶层与人生死状态）。
   从 3 km 降到 1.2 km 后，门牌视角已看不出跨城闪现。
2. **约 0.6% 人帧的 clip 名与瞬时速度不完全一致**：决策 hurry 决定小跑，
   但积水/拥挤把实际速度压低，于是「跑的动作配慢速度」。播放速率已按
   实测位移同步，不是滑步或原地跑。要严格一致得把 `RUN_THRESHOLD` 与
   `HURRY_MUL` 一起重标定，本轮没动语义。
3. **拖时间轴仍是「按时刻重建快照 + 经历清零」**，不是完整 24h 历史回放。
   本轮只修了重建时的状态残留和大步长瞬移，没有改变这个接口的性质。
   所有「今天经历了什么影响走势」的数据都只在连续运行 / 开倍率时成立。
4. 离线验收用 `skipRender=true`（子步 ≤0.4 仿真秒），实时播放子步 ≤0.2 秒，
   高倍率下精度略有差别，但同一套时钟与速度真值表。
