## 1. 问题：跨数据集的 logit 系数不能直接相加

我们有三个行为子模型，各自来自不同的问卷数据：

| 层 | 数据 | 系数 |
|---|---|---|
| 认知（是否意识到危险） | Thieken et al. 2023, Table S2 有序 logit | `female 0.493`、`offWarning 0.571`、`warningInformation 0.147`、`surprise −0.648`、`floodImpact −0.078`、`priorFloods {1: 0.68, 2: 0.901, 3: 2.01, 4: 2.001}` |
| 行动（采取什么保护行动） | Thieken et al. 2023, Table S3 | `situationalKnowledge 0.296`、`age −0.012`、`priorFloods 0.212`、`surprise −0.248`、`waterDepthOrdinal −0.28` |
| 撤离 vs 留下 | Borowski et al. 2023, Table 4 | `ASC 4.22`、`cost −3.71`(SD 1.03)、`peersRide −1.27`(SD 1.91)、`peersStay 7.76`(SD 10.87)、`travelTime −0.02`、`waitTime −0.03`、`walkDistance −1.08`、`age 0.21` |

把它们放进**一条**方程：

```
V = λ_k·(认知得分) + λ_a·(行动得分) + λ_u·(Ve − Vs) + 威胁项
p = σ(V)
```

就默认了 `λ_k = λ_a = λ_u = 1`。但这三个 λ 是**每个数据集自己的 logit 尺度**，在
各自的样本里根本估不出来（Swait & Louviere 1993, *JMR* 30(3):305–314 的标准结论：
不同数据集合并估计时，尺度参数只能识别到比值）。项目早期确实拍过一组
`0.50 / 0.80 / 0.25`——2026-11-21 已删，进 `RETIRED_SELF_SET` 留墓碑。

**结论**：单式模型的写法本身没有被数据支持；它只能当**对照组**，不能当主模型。

## 2. 五道门的定义（按时间顺序，逐层收紧）

| 门 | 名字 | 判据 | 参数来源 |
|---|---|---|---|
| 门 1 | 接收（reception） | 是否收到预警：`received ∈ {0,1}`；渠道按 `reception-channel.js` 重分配（官方/邻里/看见），职业值守人群的接收率按 `DUTY_POPULATION_SHARE = 0.089` 校正 | ACS 微样本（SOC）× 值守表 |
| 门 2 | 认知（awareness） | `HR = d·(v + 0.5) + DF`（FD2321/TR1 城市列），按 FD2320 分四级；威胁措辞 `low/some/most/all → low/moderate/extreme`（Thieken Table S1 的水深有序编码） | FD2321、FD2320、Thieken 2023 |
| 门 3 | 动员（mobilisation） | `mobilisation = F(Δt_since_warn; κ)`，`F` 是 AFT 时间轴重标：`ratio = exp(κ·(k_i − k_ref))`，`k_i` 是门 2 的认知得分，`k_ref` 是参考人（priorFloods=1）；`κ = 1` 是**唯一自由标量**，敏感性 0.5/1/2 | Hasan et al. 2013, *TR-C* 27:108–116（AFT 形式）；κ 自设 |
| 门 4 | 选择（choice） | `p = σ(Ve − Vs)`，`Ve/Vs` 见 §3 | Borowski 2023 Table 4 |
| 门 5 | 可行集（feasible set） | 三条阻碍：`no_vehicle`（户车=0 且步行距离 > 2000 m）、`on_duty`（在职值守 SOC ∈ {25,29,31,33,55}）、`care_child`（单亲带未成年，ACS 派生，1.21%） | ACS PUMS（VEH/RELP/户规模/户内未成年）、Drabek 2000/2001 |

概率写成：

```
p_action = (received && !dutyHold && !careHold) · mobilisation · σ(Ve − Vs)
```

**门 5 不改概率，只改姿态**：`no_vehicle` 把「开车走」改成「步行/就地避险」；
`on_duty` 在危险等级到 `most/all` 时自动解除值守；`care_child` 在 `most/all` 解除
（自保优先）。姿态四态：`stay_on_duty / gather_child / walk / evacuate`。

## 3. 选择层的两个效用（Borowski）

```
Ve = 4.22 + (cost + 1.03·z_cost)·cost + (peersRide + 1.91·z_ride)·peersRide
        + (−0.02)·travelTime + (−0.03)·waitTime + (−1.08)·walkDistance
        + 0.21·((age − 48)/13.2)
        + 威胁交互(peersRide)：moderate 0.50 / extreme 1.11

Vs = (peersStay + 10.87·z_stay)·peersStay
        + 威胁交互(peersStay)：moderate −9.27 / extreme −21.13
```

- `cost = 绕行英里 × 32.78 (美元/英里) / 100`（WTP 反解，单位换算在 `kernel/attributes.js`）
- 三个随机参数偏差 `z_cost/z_ride/z_stay ~ N(0,1)`，**每人三个、全天不变**
- `peersRide` / `peersStay` 由合成参照群体实时统计（`kernel/peer-share.js`）：
  同户 + 120 m 内最多 3 邻居，上限 5 人（Borowski QA9 问卷设计上限）；
  「乘车」用 `ped.inVehicle` 判定

## 4. 为什么这样拆能解释「同时出发、一起被困」

单式模型的触发是「水深 > 0 就按概率动」，于是同一片街区的人在同一个雨峰里**同时**
进入决策、同时出发；门结构有门 3 的 AFT 时间轴（按各人认知得分拉开先后），
人流被摊开。实测（`u_p8_s0`，1000 人）：单式组的「路面·被困」死亡 5 例 vs 门结构 1 例，
且单式组步行总量只有门结构的一半（6,080 vs 12,942 km）——**动得早、走不远、停在深水**。

## 5. 对照组的正式定义（论文里要原样贴）

```
# gate（主模型）
p = (received && !dutyHold && !careHold) · F(Δt; κ) · σ(Ve − Vs)

# single（对照组，两种 λ）
p = (depth > 0 && !dutyHold && !careHold) · σ(λ_k·k + λ_a·a + λ_u·(Ve − Vs) + 威胁档)
   merge: λ = (0.50, 0.80, 0.25)   # 项目 11-21 之前真用过的值
   raw:   λ = (1, 1, 1)            # 「默认尺度相同」的极端
```

两者共用：人口、水情、同伴网络、门 5、驾驶层、伤亡判据。**只换决策结构。**

## 6. 论文里必须写清的三句话

1. 「单式对照组不是稻草人：它复刻的是本项目 2026-11-21 之前的真实写法，含那三个退役缩放。」
2. 「λ 不可估，所以本文只报**方向**（死因结构、撤离时点分布、判定频率），不报绝对死亡数的优劣。」
3. 「对照组的威胁项是线性化编码（none 0 / low 0.35 / moderate 1.30 / extreme 2.60），
   这是自设；门结构里威胁是通过可行集与动员曲线间接进来的。所以比较测的是结构，不是威胁项写法。」
