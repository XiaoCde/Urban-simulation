## 一、先把「哪些借、哪些不借」说清楚

上一轮我把话说得太绝对了。文献里的**结论和量级**本来就是我们的基本盘，必须用；不能用的是「把别人某个样本的百分比，当成我们模型算出来的结果报出去」。分三档：

### A 档：直接当基本盘用，不标"待核"

| 结论 | 为什么算基本盘 |
| --- | --- |
| 水越深越难走，到腰基本走不动 | 多来源一致、方向明确、量级不依赖特定样本 |
| 车在 0.5–0.6 m 深、或水有流速时开始失控/漂浮 | 实车试验 + 事故统计同向 |
| 地下室最先淹、最危险；一层比上层危险 | 德国 2021、美国多次事件的个案库一致 |
| 预警越早，撤的人越多 | 跨事件一致；但只说方向，不说幅度 |
| 「发布预警」不等于「人收到」 | 多次调查一致，且有官方记录可比 |
| 洪水死亡以溺亡为主 | 多份个案库都在七成以上 |
| 人会看周围人：邻居都没走，自己也不容易走 | 社会影响类研究一致 |
| 涨水越快死得越多，缓涨和暴涨是两种死法 | 溃口与内涝的致死机制不同，已被反复验证 |

这八条我直接用，写进代码注释和报告，注明出处，不再每处标注"待核"。

### B 档：可以用，但要标出处、给区间

| 数 | 怎么用 |
| --- | --- |
| 7.76（同伴系数） | **保留作基准值**，用原文标准误算敏感性区间，报"死亡 A–B"而不是单点 |
| Jonkman 两条致死曲线的参数 | 保留，分区后各用一条 |
| 各文献的死亡比例（32.4% / 16% / 94% / 39.6% vs 15.1%） | 只作对照，判断我们的输出量级是否离谱；不进模型当乘数 |
| 涉水步速的三档形状 | 作参照，绝对值在 DC 重标 |

### C 档：不能直接搬

- 别人样本的比例当 DC 的比例（32.4% 那份是 13 场混合，94% 那份是澳大利亚 115 年）
- 别人场景的阈值（0.7 意图阈值、0.5 m 临界水深、150 秒耐受）——可以作起点，但必须做敏感性
- 别人网络的规模（桑迪 2.69 人）——用来**对比**，不用来**对齐**

## 二、六步，按「改不改结论」排序

### 第 1 步｜修从众的输入（半天改代码 + 2.5 小时重跑）

**现在的问题**：同伴只算「同一户的人」。一户人住一起、看到同一片水、同时决定，所以「同伴里还有几个没走」只有两种值：全在家（比例 1）或全跑了（比例 0）。而 Borowski 的系数是按连续比例估的（同伴留下 0/25/50/75/100%），输入被压成二值后，三分之二的判断顶到设计上限 0.8。

**做法**：把参照群体从「同户」扩到「同街区邻居」——用我们自己的建筑位置算：同一街区、100 m 范围内的其他户。邻居走没走是能看见的，这才是「看别人」的真实对象。**不用桑迪的 2.69 人，也不用 34.3% 这个数**，规模由 DC 的街区密度自己长出来。

7.76 不改，保留作基准。

**会变什么**：同伴比例出现中间档，死亡可能回落到接近旧值（9/26/39/48 那一批）。

**怎么验**：十档直方图里中间档占比要超过 30%（现在是 7.6%）；同时给 7.76 的敏感性区间。

### 第 2 步｜伤亡层分区（2 天 + 重跑）

**现在的做法**：全城一条 Jonkman 曲线，按水深算死亡概率。等于把溃堤、内涝、山洪当成一回事。

**改成四个区**，每区一套参数：

1. 室外涉水（走得动但危险）
2. 室外被困（水深或流速过了行动限界）
3. 车内（水淹到车门下沿、车开始漂）
4. 室内（一层 / 上层 / 地下室，三档折减）

**判据用我们自己的东西**：水模型已有逐时水深，能算涨水速率（每小时涨多少厘米）；室内外由 agent 的位置决定；地下室有单独的埋深。

**依据**：分区思路借 Jonkman & Vrijling（方法），参数保留 Jonkman 原曲线按区取用。这是"基本盘"，不用重新发明。

**会变什么**：死因构成和总数都会变。

**怎么验**：同一个工况，四区各报死多少人；总死亡和旧值比，差异要能解释（哪个区变了、为什么）。

### 第 3 步｜死因改成「地点 × 动作」（和第 2 步同批做）

**现在的做法**：死因只有四类（涉水溺亡、深水被困、车内溺亡、地下室进水），非溺亡靠一个外推列撑着。

**改成两维**：

- 地点：路上 / 车内 / 桥下与下穿 / 室内一层 / 室内上层 / 地下室 / 地下通道
- 动作：涉水行走 / 开车 / 被困 / 救援 / 清理 / 查看水泵

**好处**：能直接回答"人死在哪、当时在干什么"，跟文献的编码口径对得上（德国 224 例那份就是这么分的）。剩下"被砸、触电"确实算不了，就明确写"未建模"，不再用外推列充数。

**会变什么**：死因表结构；报告里那一列"若计非溺亡"删掉。

### 第 4 步｜时间层拆成两个时钟（1 天）

**现在的做法**：预警到达一条线 + 自设的 30 分钟重估窗口。

**改成**：

1. 预警触达时钟：从"发布"到"这个人收到"，含收不到的那部分人（现在 35% 收不到）
2. 动员时钟：从"收到"到"出发"，给分布不给常数

30 分钟重估改成由雨强变化率驱动：雨越急，重估越频繁。

**会变什么**：避险人数和出发时机，进而影响死亡。

**怎么验**：报两个数——预警触达率、平均出发延迟——和文献的量级对照（只比量级，不比精确值）。

### 第 5 步｜涉水步速改成随水深换参数（半天）

**现在的做法**：干地速度乘一个折减系数，一张表定死。

**改成**：水深改变自由速度和最大密度（基本图），拥挤时也成立。形状照实验，绝对值在 DC 重标。

**会变什么**：人走得更慢 → 暴露时间更长 → 死亡上升。方向是确定的。

### 第 6 步｜找 DC 自己的真值（1 天）

**现在**：只能证明模型自洽，不能证明跟现实对得上。

**做法**：用 DC 311 的积水投诉记录、媒体报道过的积水点做验证集。报三个数：我们算出来的积水点里，命中几个、漏了几个、多报了几个。

这是唯一能回答"跟现实对不对得上"的东西，也是评审一定会问的。

## 三、顺序与依赖

```
第 1 步（从众输入）──→ 重跑一次 ──→ 拿到新的死亡量级
                                    │
第 2+3 步（分区 + 死因）────────────┴→ 重跑一次 ──→ 最终数字
第 4 步（两个时钟）  ┐
第 5 步（涉水步速）  ┘ 可与 2+3 并行，合并到同一次重跑
第 6 步（外部验证）  ── 最后做，用最终数字
```

- 每步改之前，我先报：改哪个文件、改哪几行、预计数字往哪走
- 改完给「改前 / 改后同一个工况」的对比表
- 每个数字标明性质：模型输出 / 文献参考 / 目前自己定的
- 重跑统一固定种子 20261117，并发 4

## 四、我不做的事

- 不在没重跑的情况下改代码然后沿用旧数字（要么不码，要么重跑）
