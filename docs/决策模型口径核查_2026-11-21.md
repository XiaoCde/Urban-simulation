## 二、发现 ① 归一化把相对权重改掉了（确定是缺陷）

论文系数是**每美元 / 每分钟 / 每英里**的边际效用，但代码先把四个量归一化到 0–1 再乘。按 `BOROWSKI_DESIGN`（Table 3 印刷范围）换算：

| 属性 | 设计范围（均值） | 现状输入 | 实际放大/压缩 | 说明 |
| --- | --- | --- | --- | --- |
| cost | 0–40 USD（11.60） | 0–1（0.29） | **压缩 40×** | 40 美元理论 −148.4，实际只 −3.71 |
| travelTime | 0–60 min（25.96） | 0–1（0.43） | **压缩 60×** | |
| waitTime | 0–60 min（18.49） | 0–1（0.31） | **压缩 60×** | |
| walkDistance | 0–0.5 mi（0.18） | 0–1（1.0 上限） | **放大 2×** | 0.5 英里理论 −0.54，实际 −1.08 |

后果：真正决定"走不走"的是 `ASC 4.22`、`peersStay 7.76`、威胁档和暴露度；**"绕路太贵所以不撤"这条现实机制基本不响**。这不是"没有出处"的问题，是把有出处的系数接到错的尺度上。

## 三、发现 ② `warningInformation` 空转

`web/src/cohort.js:165` 读 `s.warningInformation || 0`，全项目**没有任何地方给它赋值**。认知层 0.147 因此恒乘 0——不是"被忽略"，是从来没有输入。已在原位加注登记为**未启用**；要接必须先找到"非官方渠道预警信息"的可观测代理量，不能拍一个 0–1。

## 四、为什么还不能直接改（关键未决）

`cost` 系数的单位没核实过。若真是"每美元"：

```
−3.71 × 均值 11.60 = −43.0        （会把 ASC 4.22 压死）
4.22 − 43.0 + 7.76×0.19 ≈ −37     → P(撤离) ≈ 0，全城无人撤离
```

论文自己会给出 ~0% 撤离率，这与其报告的选择比例不符。若系数按**每 10 美元**：

```
−3.71 × 1.16 = −4.30
4.22 − 4.30 ≈ −0.08               → P ≈ 0.48，量级正常
```

所以 −3.71 更可能以 **10 美元为单位**。在这条核实之前，把输入换成"原始美元"很可能是**用一个猜测替换另一个猜测**，反而制造"全城 0% 撤离"。

两条修法数学等价：

1. **raw**：输入按物理单位（美元/分钟/英里），系数保持论文原值；
2. **scaled**：保持归一化，系数同比例放大（cost ×40、时间 ×60、距离 ÷2）。

选哪条取决于原文 Table 3/4 的变量定义与是否做过 scale。`web_fetch` 抓 `https://par.nsf.gov/servlets/purl/10401527` 返回 HTTP 200 但正文为空（PDF 未解析），本会话读不到。
