# V6.1 四开关敏感性（2026-11-21 夜）

> **状态**：现行有效。数字可引用，但必须连口径一起引（300 人 × 5 小时峰值段 × 同 seed）。
> **一句话结论**：从众渠道会让死亡数在 8–11 之间动（成分变，不是噪声）；滑倒判据几乎不动死亡数（8→7），只决定受伤数（5→0）；把失稳下界抬到实测区间上端，死亡不变、受伤 5→7。

## 一、怎么跑的

同一批人、同一段雨、同一时长，**只改一个开关**。这样差异只能来自那个开关，不能来自「换了人」或「换了雨」。

```
cd web
node serve.js 8140                     # sim-day 需要一个静态服务；跑完关掉
SIM_<开关>=<值> node sim/sim-day.mjs 300 24 300 out/_sens_<名字>.json 1020 u_p120_s0 20261117
```

| 项目 | 取值 | 为什么是这个取值 |
| --- | --- | --- |
| 工况 | `u_p120_s0` | 傍晚两小时暴雨，全天最强档。室内与路面死亡都出得来 |
| 人数 | 300 | 与基线、与 A 组阶梯（`_cas2_s*`）同批人，能逐格对比 |
| 时长 | 300 分（17:00 起跑） | 覆盖雨峰与退水前段。**不是全天**，全天要看 8 工况重跑 |
| 人群种子 | `20261117` | 与所有历史验收同一个种子；换种子就换了一批人，不能比 |
| 每档墙钟 | 约 3–5 分钟 | 300 人比 1000 人便宜一个量级，适合扫开关 |

## 三、怎么读（这部分比数字重要）

1. **车内 5 + 地下室 1 在五档里一次没变。** 说明这两条链是被「水到人到」决定的，不是被行为开关决定的——
   从众渠道再怎么调，也调不动「开车冲进深水」和「下地下室」那批人。这恰好是论文里最该站得住的那部分。

2. **差别全在室外，且表现为「被困」这个新死因。** 阈值级联档室外只死 2 人（都是涉水行走），
   加性系数档死 5 人（2 涉水 + 3 被困），关闭档死 4 人（3 涉水 + 1 被困）。
   机制解释：阈值级联把人成批劝走（走得早、走得齐），剩下的人少、被水困住的概率也低；
   加性系数是「同伴留下抬高我自己留下」的连续拉力，会把一部分人钉在原地直到水上来。
   **这是两种机制的实质差别，不是数值抖动。**

3. **滑倒判据不决定死亡，却决定受伤。** 关掉后受伤 5→0、死亡 8→7（少的那 1 例是路面涉水）。
   所以报告里「受伤数」这一栏必须写明依赖 `SELF_SET.slipProbability`（自设 0.30），
   不能当实测受伤率报出去。

4. **失稳下界抬到 1.4 不改变死亡，只把受伤 5 抬到 7。** 说明「D·V 到 1.2 就站不住」这条判据
   对致死链不敏感（致死靠浸泡时长，见 `cas.exposure`），对受伤链敏感（±2 例）。

5. **单次运行、单一 seed、5 小时窗口**：8 vs 11 这种量级差（3 例）不能乘 24 小时外推，
   也不能拿来算「每千人死亡率」。它的用途只有一个——回答「换个从众口径，你的结论会不会翻」。
   答案是：**死亡总数在 8–11 区间移动，死因结构会变（是否出现「被困致死」），但「车内与地下室是主死因」不翻。**

## 四、还没解决

- 三档从众只在 300 人/5 小时上比过，**没有在 1000 人/全天**上比（那要 8 工况重跑跑完、再抽 2 个工况换开关复跑）。
- 受伤数的敏感性只测了两端（关掉 / 下界 1.4），中间的 `0.15/0.30/0.60` 概率档还没扫。
- 「被困致死」在基线档为 0，在另两档出现 1–3 例：这条死因的行为路径（为什么留在原地）还需要
  用个体追溯（`web/src/trace.js` + `tools/trace/`）挑一个被困者逐分钟复现，否则只能说「机制上讲得通」，
  不能说「我知道他是怎么被留下的」。
