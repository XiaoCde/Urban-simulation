## 七、这一轮核出来的问题

1. **Borowski 同伴搭车标准差**：原文印 −1.91，代码 1.91。数值等价（标准差取正），但注释要写明原文是负号，否则以后有人拿原文对会觉得写错。
2. **Ahsanuzzaman「跨情景均值 0.25」**：是九项比例算出来的，不是原文印刷值。台账里要标成计算值。
3. **Silva 曲线的性质**：底层是化学泄漏、危险品、火山、山洪的案例，不是内涝实测。现在代码注释写了「跨灾种」，但《依据台账》里的表述还不够狠，容易被读成内涝实测。
4. **`floodFloor()` 有一段不可达分支**：`best >= 1 && best <= cur` 时返回 `moveUp` 到更低的层。因为楼层高程单调递增，水从下往上淹，这个分支实际进不去；但一旦进得去，会让人往楼下走。应改成原地待援或按 drowning 处理。属于「现在不触发、但逻辑错」。
5. **两个坏 PDF**（见第五节）要标注，别在后续轮次被当成「已读」。
6. **地下室的水深用的是室外地面水深**（`incidents.js` 里 `const dExp = depth`，地下室的人直接走这段）。这是这轮「地下室不真实建模」的简化，但它有一个方向性偏差：地下室地板在室外地坪以下 2.2 m，水从窗井、门洞灌进去以后，按连通器原理，坑里的水深应该是「室外水深 + 2.2 m」减去排水能力，比室外深得多。现在按室外深度算，等于**低估地下室的危险**。p8 那种小雨无所谓（原来 44 人下去、0 人死亡正说明这一点），但 p120 两小时暴雨下这个简化会明显偏轻。要么后续按连通器补上，要么在报告里明确写「地下室伤亡被低估」。
7. **死因结构缺「非溺亡」**：Jonkman & Kelman 2005 对 13 场洪水 247 名死者的统计是约三分之二溺亡，其余是创伤、触电、心脏病等。我们的死因（深水／涉水／车内／地下室／顶层被淹没路可退）全是溺亡，缺掉的那三分之一没有对应机制——这会让总数偏低，而且没有流速场，「被冲走撞伤致死」这一大类本来就缺失。**2026-11-17 补一条独立的量级参照**：Jonkman, Maaskant, Boyd & Levitan (2009), *Risk Analysis* 29(5):676–698, DOI `10.1111/j.1539-6924.2008.01190.x`，对卡特里娜 771 例死亡个案，约三分之二为直接物理作用且多为溺亡、三分之一为灾后公共卫生原因，近 60% 死者超 65 岁，暴露人口总体死亡率约 1%。该文是飓风溃决情境，全文未取回，不能当 DC 内涝的死因分布用，详见 `docs/文献核查补录_2026-11-17.md`。
8. **新发现一处二手转引误差（2026-11-17）**：UNSW WRL Technical Report 2015/09 §4.2.8 把快速涨水区 Eq.7-6 的 μN 印成 **1.48**，而 Jonkman 2007 博士论文原稿 p.206 与 §7.4 汇总公式印的是 **1,46**（欧式小数点逗号），σN 两处都是 0,28。代码 `kernel/fatality.js` 用的是原稿的 1.46 / 0.28，**正确**；以后不要拿这份二手报告去「纠正」代码。同一份报告印的 2.00 / 5.20 与 FD=0.053 是第 8 章新奥尔良个案，正好印证 `fatality.js` 头部那段第五轮纠错记录。
