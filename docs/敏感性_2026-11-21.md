# 敏感性 2026-11-21（V6 口径，单变量）

配套文档：`docs/口径表_V6_2026-11-21.md`（判据与参数的冻结版）。这份只回答一件事——**每个可争议的标量动一下，结果会往哪走、走多少**。

## 一、怎么跑的（协议，不许省）

固定：`u_p80_s0`（傍晚 80 mm/h 脉冲）· 1020→1200 分（3 小时）· 400 人 · 种子 20261117 · 时间层开 · 冲走判据关。
每一轮**只改一个开关**，源文件一行不改（所以基线是同一批代码、同一批人）。

```bash

node tools/sens/summary.mjs web/out/_sens
```

基线（全部默认）：**死 4 / 累计困 5 / 伤 12 / 避险 25 / 涉水 0 / 最深 240 cm / 判断 1,142,611**。

读法（400 人 3 小时，死亡个位数，±1 人没有信息量）：

- **受伤 100% 来自 D·V 判据**。关掉它，受伤从 12 直接归零；放宽下界（0.35）涨到 16，收紧（上界 1.4）掉到 11。所以之前 v6 两工况「伤 3→102」确实是这条判据在主导，不是别的东西。
- **从众两条口径在这段样本里给出同样的伤亡**，但判断数各涨 ~11 万——阈值级联比加性系数更"抠"，它让更多人多想几次。分不出来是因为样本太小（3 小时、400 人、避险只有 25 人），要看差别得上整天族。
- **κ 只动门 3**，死亡不受影响（这段里没人因动身早晚死在临界上），但 `kappa2` 多 2 人避险、多 2 人受伤 —— 方向对：经验越强，动身越早，路上风险也越早暴露。
- **接收比例（门 1）影响很小**：`recvratio=0.5` 与 `2` 的 Δ死都是 0。这不是"没接线"，判断数变了（−9,813 / +648）说明开关生效，只是 3 小时窗口里收早收晚还没有改变谁活谁死。

## 三、排水 C：解析算，不用重导

`served = min(1, Q/需求)`，需求是固定值（实测自 `shallow2d.py` 的打印行）：

| 工况 | 需求 m³/s | C=0.60 (192) | C=0.714 (228) | C=0.80 (255) |
| --- | --- | --- | --- | --- |
| p8 | 140.8 | 100% | 100% | 100% |
| p16 | 159.7 | 100% | 100% | 100% |
| p24 | 178.6 | 100% | 100% | 100% |
| p32 | 197.5 | **97.2%** | 100% | 100% |
| p80（脉冲） | 310.9 | **61.8%** | **73.3%** | **82.0%** |
| p120（脉冲） | 405.3 | **47.4%** | **56.2%** | **62.9%** |

结论：**全天均匀族对 C 几乎不敏感**（三档全 100%，p32 只在 C=0.60 时掉到 97%），**只有傍晚 80/120 两档随 C 线性变**。所以「C 从 0.80 改成 0.714」对全天族的结果没有解释力，之前拿它解释 v2→v6 的差异是错的。

（这张表是解析的，不需要重导水深帧；真正重导还要连流速场一起，约 4 小时。）

## 四、这轮跑出来暴露的三个开关 bug（都已修）

1. **`?recv=off` 是空转**。门 1 的实现是「保均值重分配」，默认 `ratio=1` 就等价于关闭；所以 `recv=off` 与基线逐位相同（第一次跑出 Δ判断 = 0 才发现）。这个开关留着无害，但**不能当敏感性用**，敏感性要用 `?recvratio=`。
2. **门 1 的权重根本没进「收不收得到」**。`receiveAtOf(publishMin, i)` 内部调 `receivesWarning(i)` 没传值守身份，而 `warningStageOf(i, duty)` 传了 → 权重只影响分段、不影响接收。已给 `receiveAtOf` / `departAtOf` 加可选 `isDuty` 并在 `web/src/ped.js` 把 `dutyPerson` 提到调用点之前透传（原来它定义在调用点之后）。
3. **`?sliplo=1.4` 会把判据弄得比基线更狠**。判据是 `p = dv>=hi ? 1 : (dv<=lo ? 0 : (dv-lo)/(hi-lo))`，只把下界调到 1.4 而上界仍是 1.2 → 所有 `dv≥1.2` 直接判受伤（受伤 12→17）。已新增 `?sliphi=` 单独调上界，并在代码里强制 `lo < hi`。

这三条都是**单变量跑出来的**，不是看代码看出来的——这正是把「动六处只报总数」禁掉的价值。
