# 工作场所楼层：此前整条链路缺失（2026-11-21）

## 一、缺的是什么

v2 结果里「工作场所楼层不判」这条遗留（`docs/8工况v2结果_2026-11-20.md` §五）不是参数没调，是**整条链路没建**：

| 环节 | 住宅 | 工作场所（改前） |
|---|---|---|
| 建筑 | 真实建筑，`crowd-life.js:376` 调 `assignFloor` | 池化门牌 `work_${status}_${key}`（`crowd-life.js:505`），没有真实性建筑 |
| 层数/层高/首层高 | `homeFloors / homeFloorHeightM / homeFoundationM` | 无 |
| 摆位楼层 `floorRelY` | 有 | `spotOf` 只认 `placeKey === 'home'`（`crowd-life.js:532-544`）|
| 交给伤亡层 | `where === 'home'` 才带 `totalFloors/floorHeightM/foundationM`（`ped.js:2033-2044`）| 恒为 0 |

后果：`incidents.js:363` 的楼层淹没分支 `if (indoor && tf > 0 && depth > 0.05)` 对上班的人**恒不成立**，白天在办公楼里的人被拿地面水深判死。方向是**高估**——三层办公楼里 1.2 m 深水，人其实在二楼。

## 二、怎么改的

1. `web/src/main.js`（`BIDX` 建 rects 处）：把 `bd.function`、`bd.name` 带进 rect，此前只带几何与高度。建筑职能来自 `web/assets/city/buildings.json` 的 OSM `building:function`（office 195 / government 26 / university 72 / school 29 / hospital 4 / retail 62 / commercial 45 栋）。
2. `web/src/crowd-life.js`：新增 `WORK_FN` 映射（office→office|government|public|civic|commercial|hotel，school→university|school|dormitory，clinic→hospital|pharmacy，cafe→retail|commercial|kiosk|hotel），按人自己的 `workPlace`（来自 `SOC_TO_PLACE`）挑**真实建筑**，再用**该栋自己的 function** 调 `assignFloor`，写入 `workBuilding/workFloors/workFloorHeightM/workFloor/workFloorY/workIndoor/workFoundationM`。露天岗位（site/street）与没匹配到楼的人仍走池化门牌。
3. `web/src/crowd-life.js` 的 `spotOf`：`floorRelY/floorNum` 从「只认 home」改成 home 或 work 各取各的；`at()` 的 `totalFloors/floorHeightM/foundationM` 按此刻 `where` 取对应那栋。
4. `web/src/ped.js`：`INC.tick` 的 ctx 传 `where: q.where`，并把三处 `q.where === 'home'` 放开为 `home || work`。
5. 新增两个验收出口（不是装饰，是这次排障必须的）：`window.__ped.buildingStats()` 数「住宅/单位各有多少人落在真实建筑、拿到层数」；`incidents.stats().floorTicks {home, work}` 数楼层淹没分支按地点各触发多少次。

## 三、排障里踩到的四个坑（都是静默失败）

1. **代码块放错分支**：第一版把工作场所分配写进了「没挑到住宅楼」的 `else` 里。全城 400 人都有真实住宅，这个块一次也没跑。`buildingStats()` 显示 `workReal=0` 才发现。
2. **加了口径没加数据**：`WORK_FN` 依赖 `r.fn`，但我没在 `main.js` 里给 rect 加 `function` 字段 → 匹配池永远是空的。代码看起来完全正常，结果恒为 0。
3. **`ctx.where` 没传**：`floorTicks` 全记在 `home`（一百万次）而 `work` 恒 0。看起来像「没人上班」，其实是记账位置错。
4. **`reset()` 抹掉分类计数**：`incidents.reset()` 旧写法「非数字字段一律置 `{}`」，把 `floorTicks` 清成空对象，之后 `+= 1` 变 NaN，序列化后整个字段消失（实跑表现为只剩一个 `null` 键）。已按字段给回零值结构。

第 2、3、4 条的共同点：**改了代码没改数据通道，或者数据通道对了但记账位置错了，结果全是 0，且不报错**。所以这次加的两个计数出口要留在代码里，下次改动直接看它们是不是 0。

## 四、验证

- 同步口径：`node web/tests/run-node-checks.mjs` → 17/17 全绿。
- 人群归属（`buildingStats()`，400 人、seed 20261117）：住宅真实建筑 400/400、拿到层数 399；单位真实建筑 **270/400**（office 122、cafe 47、school 88、clinic 13），室内 260；露天 18 人（site 9 / street 9）不进楼。
- 分支触发（u_p24_s0，1000→1200 分，400 人）：`floorTicks {home: 1,322,686, work: 7,527}` —— 工作场所这条路确实跑起来了。
- 全天两工况（u_p24_s0、u_p80_s0，1000 人、1440 分、seed 20261117）已启动，结果见 `web/out/v6/`。

## 五、依据与限制

- 层高、每层容量、首层高沿用 `web/src/kernel/floors.js`：办公 3.8 m、住宅 2.7 m（Choi 2002）、未标注 3.3 m；人均楼面住宅 46.5 / 办公 47.1 m²。**外推到 DC 2–4 层建筑是限制**，不是本地实测。
- 职能匹配用 OSM `building:function`，是「这栋楼登记作什么用」，不是「这家公司在这一栋」。
- 上班这件事本身仍是情景：谁上班、上几层、公司规模都不在 ACS 微样本里。这套改动只回答「人在楼里时按楼判」，不回答「他今天是否真的在上班」。
