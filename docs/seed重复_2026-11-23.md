# seed 重复：同一水情换三个种子（2026-11-23）

> 目的：挡审稿人第三枪「你只有一个 seed，怎么知道结论不是抽样偶然」。
> 数据：`web/out/seeds_v1/`（2 个新 seed）+ `web/out/sweep_v62/`（主结果 seed 20261117）。
> 生成方式：`bash web/sim/run_seeds_v1.sh`（1000 人 · 1440 分 · 并发 2）。

## 一、设置

| 项 | 值 |
|---|---|
| 工况 | `u_p16_s0`（全天 16 mm/h）、`u_p120_s0`（傍晚暴雨 120 mm/h） |
| 种子 | 20261117（主结果）、20261123、20261129 |
| 人数 / 时长 | 1000 / 1440 分 |
| 只变什么 | 只换 seed（人口抽样、行为扰动、路网选择都随 seed 变）；水情、网络规则、参数全部相同 |
| 同时长 | 每 run 约 70–80 分钟（并发 2） |

**为什么只做 2 个工况 × 3 seed**：8 工况 × 3 seed ≈ 24 run ≈ 16 小时排不下。选的是「弱驱动」与「强驱动」两端各一个，用来回答「结论对 seed 稳不稳」，不是用来算每个工况的置信区间。

## 三、三条结论（可直接写进论文）

1. **过程量对 seed 极稳，伤亡数不稳。** 判断次数 CV：p16 **0.2%**、p120 **1.5%**；而死亡数 CV：p16 **4.2%**、p120 **20.5%**。也就是说「多少人做了多少次决策」几乎不随 seed 变，「谁最后死了」很随 seed 变。
2. **所以死亡数只能报区间，不能报点。** 论文里写「p16 死亡 27–29（3 seed，n=1000）」「p120 死亡 17–25（3 seed，n=1000）」，不要写「p120 死亡 25」。p120 基数小（个位数到二十几）且强驱动下由「水到人到」主导，这个区间正是它的真实不确定性。
3. **消融结论不受影响，反而更硬。** 门结构 vs 单式的判断次数差是 **27%**（0.72–0.74×），是 seed 抖动（≤1.5%）的 **约 18–19 倍**；而两者的死亡数差（−4/+1/+1）本来就落在 seed 抖动之内（p120 单工况抖动就有 ±8 人）。这条同时解释了「为什么不能拿死亡数当决策结构优劣的判据」。

## 四、边界（别过度解读）

- 只有 3 个 seed、2 个工况；要给本文每个工况的置信区间，至少 5–10 seed × 8 工况，当前机器时间不允许。
- 报的是**极差与 CV**，不是 95% CI（n=3 算不出有意义的 CI，硬算会给人「统计严谨」的假象）。
- 单城（华盛顿 DC）、1000 人上限、堤顶常数——这三条与 seed 无关，仍是限制。
- 这 4 个 run 是 2026-11-23 04:56–07:13 用 V6.2 代码跑的（合成网络 + 门 5 三条 + 受伤累计口径），与 `sweep_v62` 同版本，可与主结果并排；**不可与 `sweep_v61`（旧同伴网络）并排**。
