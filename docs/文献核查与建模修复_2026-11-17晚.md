# 文献二／三核查、依据升级与建模偏差修复（2026-11-17 晚）

这一轮做了三件事：把用户新给的两批文献逐份核到原文、把代码里「转述」的依据升级为一手原件、直接修掉五处已知建模偏差。**没有重跑 8 工况**——按用户指示，等后续完善齐了一起跑。

## 一、核到的原件与依据升级

文献二 18 个文件（去重 16 份）、文献三 6 份 PDF 加一个 529 文件的 PKU-FIM 仓库，全部可正常打开，没有坏文件或拦截页。逐份的机构、年份、卷期页码、样本量、SHA256 见 `from muse/数据来源.md` 第 19、20 条，这里只说结果。

**六个数值组与代码逐条对上**，代码注释里「本地无原件、按转述沿用」的标记全部摘掉：

- 失稳界值：ARR Project 10 Stage 1（2010）p.8–9、25–29 印的成人 D·V<0.6、受训 0.8、多数失稳>1.2，儿童 D·V<0.4、最大水深 0.5 m，与 `params.js` 六个值一致。
- 车辆涉水：WRL TR 2017/07 p.53 小型车 0.15 m、p.49 Patrol 0.45 m 与 0.95 m、p.25–26 图 5-5 Yaris 0.6 m，四个值全对上。
- 步速：Bohannon 2011 Table 2（p.3）、Weidmann 1993 第 2 版（p.44–54 的 1.34 m/s）都对上。
- HR 公式：FD2321/TR1 p.10 §3.5 是 `d×(v+0.5)+DF`，2008 年环境署澄清说明明确这是最终版，TR1 第 3.2 节的 `d×(v+1.5)+DF` 是 Phase 1 旧式；碎屑因子城市列与 Table 3.1 逐格一致。**代码公式没错，只是出处被旧注释误记成 TR2，现已改正。**

**两处性质错误，这是核原件才看得见的**：

- PNNL-26949 的 3.95 m 不是实测层高。报告 p.17 明写 CBECS 既没有 floor-to-floor height 也没有 building height，这个值是用 floor-to-ceiling 加「presumed」假设估算的。代码把它标成「模型跑出来的数（不是实测）」，不能与 Choi 2002 的实测分功能层高混用。
- NCHRP 562 全文没有印 0.34。报告 p.36–43 按 9 类过街设施、60 个站点给出 motorist compliance 的范围与均值，0.34 以及代码里的 0.07–0.75 都是跨站点汇总量，不是单站实测。步长 1.1／0.9 m/s 倒是与原文一致。代码注释已写明，数值没动。

## 二、直接修掉的五处建模偏差

这些会改变仿真数字，但用户明确要求「直接做、等完善了再跑」，所以只改代码，不重跑已交付的 8 工况。

| 偏差 | 改法 | 代码位置 |
|---|---|---|
| 地下室人按室外地面水深暴露，系统性低估危险 | 室外水深过 0.05 m 进水阈值后，当地水深改为 `室外水深 + 2.2 m 埋深`；滑倒判定同步改用当地水深 | `web/src/incidents.js` |
| 檐下人无条件「受保护」，脚边 2 m 深水也完全不暴露 | 檐下只在水深低于成人失稳下界且未到深水阈值时才保护，超过后落到涉水暴露段 | `web/src/incidents.js` |
| 楼层容量用外接矩形当占地面积，L 形／细长楼高估每层人数 | 把真实 `area_m2` 从建筑数据传进 rect，优先用真实值，缺值时回退并记录 `homeAreaSource` | `web/src/main.js`、`web/src/crowd-life.js` |
| `totalFloors` 是字符串时 `Number.isFinite` 为假，整段楼层淹没判定被静默跳过 | 显式 `Number()` 转换后再判 | `web/src/incidents.js` |
| 没有绕路时按到目标的总距离收费，与「每多走一英里补偿」口径不符 | 绕路成本只用 `detourMetres`，没有绕路就是 0 | `web/src/kernel/attributes.js` |

**验证**：新增 3 条回归断言（无绕路不收费、地下室常数、真实面积优先），内核边界自检 63/63；自检总入口 13/13；浏览器回放验收 8/8；全目录语法检查 0 错误。原有的第四轮证据自检里有一条断言是按旧错误口径写的（没绕路也收费），已改成正确口径并补一条反向断言。

**当前已交付的 8 工况数字是旧口径，不再对应现在的代码。** 这一点在对外表述时必须写明，等重跑后整批替换。

## 三、文献带来的方法启发（没有接入代码，只是记下来）

**ARR 提供了儿童分档的实测依据，但暂不能直接接。** 它按身高×体重积 H.M 分档（成人>50、儿童25–50、幼儿<25），比项目自己取的 13 岁有依据得多。但项目人群数据只有年龄性别，没有身高体重，要先找到分布数据才能替换；在此之前 13 岁继续标「目前自己定的」。

**ARR 直接质疑了项目正在用的 HR 分级。** 原文 p.22 指出这套分级没有水深上限，深水低流速可能判成低危险「不切实际，因为人一旦浮起来就是 inherently unstable」，而且「几乎所有儿童在低危险区也无法站稳」。这是对项目核心危险判据的方法论质疑，不是补个系数能了结的。已经在代码注释里写明「HR 是工程判据，不是实测剂量–反应函数，不能当死亡判定」。是否要动 `hazardRatingValue` 的深水静水判定，属于会改数字的更大改动，本轮没做。

**PKU-FIM 的价值是当对照，不是拿来跑。** README 说核心 ABM 按补充算法 1–9 构建，但仓库全库搜不到 `repulsion`、`herding`、`agent-based`，核心模型脚本没发布；验证脚本还依赖仓库外的 `Simul_env.pkl` 和 `OutputData/`，跑不起来。它的三条规则（躲避危险／趋向安全区／与同伴一致）正是项目需要讲清区别的那类网格触发式框架，而项目坚持自我中心社会网络、宁可让从众支路留空。许可证是 GPL v2，复用前要评估。1-km 人流 CSV 只有网格 ID 和流入量两列，21 个中国城市 100 年一遇情景，不能当 DC 的校准目标。

**验证框架有一整块可借鉴**：手机信令做真值、混淆矩阵与准确率、高斯平滑、1000 次 bootstrap 给 95% 置信区间、避难所需求—供给匹配。项目现在只做到自检断言和 8 工况横向对比，没有外部真值校准和不确定性区间。这条列为后续事项，本轮没做。
