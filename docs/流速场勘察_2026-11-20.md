# §3 流速场：现状、代价、能不能做（勘察稿 2026-11-20）

> 状态：**只勘察，没动代码**。结论先说：能做，但要重算八档水动力，代价以小时计，不是本轮的事。

## 一、为什么缺的不是「速度」而是「出口」

`tools/flood/swe_numba.py` 是浅水方程求解器，**每一步都在算流量**：

- `:297-298` 构造时 `self.qx = np.zeros_like(h)`、`self.qy = np.zeros_like(h)`（单位宽流量 m²/s）。
- `:330-342` 每个方向都是 `_flux_x → _lim_x → _apply_x` 四步，`qx/qy` 是中间状态。
- 所以格心流速就是 `u = qx / h`、`v = qy / h`（`h` 为水深），**算的时候就有，只是没落盘**。

落盘的只有水深：`web/assets/flood/<case>/f000…f031.u8`，8 m 格、`quant_pow=2`、`scale=4`，
外加 `manifest.json`（`cols=747, rows=640, x0=-1277, z0=-4189, step_m=8`）。

前端 `web/src/flood.js` 的 `sampleAt` 只对这些 u8 做双线性 + 帧间线性，没有第二个通道。
**所以「补流速」= 改 Python 导出 + 重跑八档 + 改 JS 采样器 + 改伤亡判据，四件事，不是一件事。**

## 二、重跑的代价

- 八档工况各 1440 分钟，帧间隔 45 分钟（`build_unified.py:51-54` 的 `--frame-min 45`，32 帧铺满一天）。
- `swe_numba.py` 头注释给的量级：1.9 M 格、每步 ~0.3 s、6 小时场景 ~50 min。
  1440 分钟仿真步长按 CFL 自适应，实际墙钟要看 `stats.json` 里记录的 runtime。
- 结论：**八档重算 ≈ 半天到一天**，且必须整族重算（半族新旧混用会导致同一份报告里两套水）。
  因此这件事只能在「已经决定要出 v3 结果」的时候做，不能顺手做。

## 三、导出方案（如果做）

1. Python：在帧写出处多写两份 u8，`u`/`v` 各一，量化 `round(127 + 254 * clamp(v, -1.5, 1.5) / 1.5)`
   （即 0.0118 m/s 分辨率、±1.5 m/s 量程），零流量恰好 127；`manifest.json` 加
   `vel_scale`、`vel_offset`、`vel_files`，老工况缺字段时前端自动降级为「无流速」。
2. JS：`web/src/flood.js` 加 `velocityAt(x,z,t)`，与 `depthAt` 同一套时空插值；
   缺帧/缺通道一律返回 `null`（**不是 0**），调用方必须显式处理。
3. 判据：现在 `web/src/motion-units.js:56-91` 的 `CAR.STALL_DEPTH`、`RISK` 与
   `web/src/kernel/thresholds.js:87-115` 的被困/滑倒阈值**只用水深**。
   加速度后必须新增「水深 × 流速」的联合判据，且**每个阈值都要有出处或明确标「目前自己定的」**。

## 四、诚实的话：流速的「死」目前没有可引的 DC 依据

- 项目文献库里能用的只有 Li 2026（静水泳池、大学生、单向流、零流速），它明确说
  **不能用来推断流速下的失稳**（`:1913-1933`）。拿它当流速判据就是越界。
- 工程上常见的「成人 0.5 m/s 失稳、儿童 0.3 m/s」属于洪水安全指引（FDOT/Austroads 那类），
  不是本项目的实测，也不是 DC 的观测。要用就必须写成「引自工程指引，未在本地验证」。
- 更保守的做法：先只把流速**当暴露指标**导出（「有多少人·时处在 >0.5 m/s 的水里」），
  不进死亡判据。这样它立刻有信息量，又不假装我们知道流速怎么致死。

## 五、与 §6 的关系

流速场最大的价值不是多死几个人，而是**让「冲走」这条路存在**。
现在 `web/src/kernel/floors.js:271-273` 自己写着「冲走/倒塌/上屋顶三类不在本模型内」。
在只有水深的模型里，「死」几乎只能发生在室内低层（地下室、首层），
室外涉水者顶多被困——这也是为什么八工况白天死亡这么少、而死因表里地下室一项独大。

换句话说：**§3 不做，死亡结构就永远是「室内淹死」单一口径**，这件事要在报告里讲清，
而不是让读者以为「室外涉水很安全」。
