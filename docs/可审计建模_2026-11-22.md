# 可审计建模：把「每个数字都要有出处」做成机制（创新点 ②）

> 创建 2026-11-22。这份文档回答的是审稿人和导师都会问的一句话：
> 「你的参数是怎么定的？」——不是给一张表，而是说清楚这套工程**怎么防止参数
> 变成拍脑袋、怎么防止接了线却静默不生效**。
>
> 现状：58 条在跑常数全部登记、619 项机检、四条跑批绊线、三处真实抓错。
> 文件：`web/src/kernel/param-registry.js`、`web/tests/check-param-evidence.mjs`、
> `web/tools/check/param-table.mjs`、`web/sim/tripwires.mjs`、
> `docs/参数依据表_V7_2026-11-21.md`、`docs/口径表_V6_2026-11-21.md`。

---

## 一、问题不是「没有依据」，是「依据不可核对」

导师的原话是「决策模型有限状态机 + 经验系数（1.55/0.35/0.8）缺文献支撑」。这类
批评的杀伤力在于：**听众没有办法当场验证你说的是真的**。哪怕 90% 的常数都有出处，
只要有一个是拍的，整张表就不可信；而人一旦发现一个，就会怀疑全部。

所以这里的目标不是「把出处写漂亮」，而是三条可执行的要求：

| 要求 | 反例（真实发生过） |
|---|---|
| 每个在跑的数字，能一句话说清「哪来的」 | 「压缩包里有这个词，应该就是它」 |
| 数字一旦被改，机检要立刻红 | 改了系数，测试全绿，因为测试断言写的是另一个字段 |
| 接了线的东西必须真的会发生 | `peersRide` 挂了系数，输入恒 0；`RUFAT_CUE_LADDER` 挂着 `wired:false` |

第二、三条是这套工程最值钱的部分：**「看着接了、实际从来不发生」是本项目里反复出现的
同一类 bug**（下面三个案例全是这一类），而它恰恰是传统 ABM 论文最难自证清白的地方。

## 二、三层结构（登记 → 机检 → 绊线）

```
             ┌──────────────────────────────┐
   58 条常数 │ param-registry.js  ENTRIES    │  性质/出处/为什么/敏感性/探针
             └──────────────┬───────────────┘
                            │ 生成（不手写）
                            ▼
             docs/参数依据表_V7_2026-11-21.md   人读的一页纸（84 行表格）
                            │
                            ▼
             ┌──────────────────────────────┐
   619 项机检 │ check-param-evidence.mjs      │  出处格式/why 长度/探针在位/真值一致
             └──────────────┬───────────────┘
                            │
                            ▼
             ┌──────────────────────────────┐
    4 条绊线 │ sim/tripwires.mjs → sim-sweep │  断流/ETA/NaN/结果合理性
             └──────────────────────────────┘
```

### 2.1 登记：58 条，六种性质

每条常数必须落进六类之一（`KINDS`）：

| 性质 | 条数 | 判据 | 回答方式 |
|---|---:|---|---|
| 真实数据集 real | 3 | 数据文件名 + 列名 + 加权口径 | 「ACS PUMS 的 PWGTP 加权，列名是……」 |
| 文献实测值 measured | 25 | 作者-年份-表号/图号，可翻到 | 「Borowski 2023 Table 4，系数 −1.27」 |
| 按公式推导 derived | 4 | 写出公式，别人能重算 | 「Q = C·i·A = 0.714×0.0376×30.6 km² ≈ 228 m³/s」 |
| 目前自己定的 selfSet | 21 | **必须写 why（≥30 字）+ sens（怎么扫）** | 「为什么是这个数 + 扫过哪几档 + 明说没有一手依据」 |
| 工程/表现参数 engineering | 5 | 必须写明「不进结论」 | 「这是渲染和观感参数，不参与任何统计」 |
| 已退役 retired | — | 保留墓碑与退役理由 | 「这五个缩放为什么删掉」 |

每条还带一个 `probe`：源文件里必须仍然存在某个字面量（正则）。作用是防止
「表里写着有，代码里已经删了」和反向的「代码里改了，表没改」。

### 2.2 机检：619 项，哪一类错都能红

`web/tests/check-param-evidence.mjs`，现在 619/619 通过。它检查的不是「文档写得好不好」，
而是下面这些**会真实导致数字不可信**的情况：

- 性质不在六类里、实测值却没有年份/表号/DOI、数据集没有列名；
- `selfSet` 没写 `why`（<30 字）或没写 `sens`；`derived` 没写公式；`engineering` 没说「不进结论」；
- `probe` 指向的文件不存在（曾把 `web/src` 目录当文件）、或字面量已经不在源文件里；
- `get()` 读到的运行时真值 ≠ 表里印的 `expect`（改了代码没改表）；
- 登记表声明的覆盖模块（13 个）里，有模块没有登记项；
- 未接线输入的四个字段（`where/whyZero/effectBound/liftRequires`）不全；
- **反向防呆**：某条已知「本该恒 0 的输入」如果突然有了赋值，测试要红。

### 2.3 绊线：跑批的失败不再无声

过去真实发生过三件事：23:17 断流到次日 10:27 没人知道；p24 用 420 s 只跑到 320 分
没有报警；v4 死 97（基线 21）照样跑完。所以 `sim/tripwires.mjs` 给了四条：

| 绊线 | 判据 | 曾经踩过的坑 |
|---|---|---|
| 断流看门狗 | 结果文件 size/mtime 8 分钟不动 → SIGKILL 并标「不进结果表」 | 静默 11 小时 |
| ETA 偏离 | 与**同族已完成工况墙钟中位数**比，>1.35× 告警；收尾再整场复核 | 第一版用「首次线性外推」，实跑 1.57× 全是误报（干地帧便宜、雨帧贵）；同工况两次 491s/559s ⇒ 跑批自身抖动 1.14×，阈值不能压到 1.35 以下 |
| 结果合理性 | NaN 扫描（给出 `$.a.b` 路径）+ 死亡数跨雨强逆转提示（低基数不比、不阻断入表） | 曾拿「同批死亡中位数」当基线 → 3 个干净工况被判异常（8 mm/h 本来就不该和 120 mm/h 一样） |
| 状态量越界 | NaN/Infinity 一律不进表 | — |

## 三、三个真实抓错（这是本节的核心证据）

三次都是同一类错误：**接线了，但线上永远不触发**，而且测试全绿。区别只在「怎么被抓到」。

| # | 现象 | 根因 | 怎么被抓到 | 修复与回归 |
|---|---|---|---|---|
| ① 照护责任恒不触发 | 门5 第三条 `care_child` 加权命中 **0 人**（本该 1.21%） | `HOUSEHOLDER_RELP` 写了旧版 RELP 码 `01/02`；ACS PUMS 用 `20/21/22` | 用真实微样本现场重算占比 → 0，与「应该有」不符 | `HOUSEHOLDER_RELP = ['20','21','22']`；`check-care-child.mjs` 28 项，其中一条直接从 `data/real/acs_dc.json` 重算 1.21% 并要求 >0 |
| ② peersRide 恒 0 | Borowski 的「同伴乘车」系数 −1.27 与威胁交互项贡献为 0 | `live-agent.js` 只给了 `peersStay`，`peersRide` 从未赋值 | 读代码发现「系数有、输入没有」；grep 全项目无赋值点 | 新建 `kernel/peer-share.js`（`peerShares()` 按 `ped.inVehicle` 分类）；`check-peer-share.mjs` 18 项 |
| ②b peersStay 方向反了 | 开车撤离的人被算成「留下」，同伴开车走反而抬高「留下」 | 旧 `peersStayOf` 只排除 `mode==='flee'\|'shelter'` | 对着 Borowski QA9 的变量定义逐字核 | 同一份 `peerShares()` 一起改；测试钉住「开车撤离者 peersStay=0」 |
| ③ 无车户也能开车 | `hasCar=false` 的人仍能开走一辆车 | `traffic.js bindCrews` 第二轮 `if (!used.has(i))` 无条件补车 → 无车户获得车主身份 | 追个案：某人 ACS 户车 0，却出现在驾驶请求里 | 只给 `hasCar && license` 配车、删无条件补车；`check-no-car-no-drive.mjs` 16 项 |
| ④ 整批结果静默作废（2026-11-22，**最新最贵的一次**） | 8+3 个工况 `exit 0`、日志跑到 100%，但每份 JSON 的 `final.sim` 是 `null`，所有指标（死亡/被困/受伤）读出来都是 **0** | 我在 `sim/sim-day.mjs` 的 `page.evaluate()` 闭包里写了 `Number(process.env.SIM_CASES_MAX \|\| 12)`——闭包在**浏览器**里跑，那里没有 `process`，于是每次收尾快照都抛 `process is not defined`，被 `catch` 吞成 `final.error` | 跑完第一个工况后**手查 JSON**：`final.error: process is not defined`、`final.sim: null`。如果不查，`decide-ab` 会把 gate 和 single 的「0 死亡」并排成表，看起来像是「两种结构没差别」——**一个假结论** | 改成 Node 侧读 env → URL 参数 `casesmax` → 闭包形参 `(casesMax)`；`sim-sweep` 显式拒绝 `final.error`／`final.sim=null`；`decide-ab` 直接 `[refuse]`；新增 `check-cases-export.mjs` **13/13** 钉住「闭包里不许出现 process」 |

**教训（写进文档，不写进心里的那种）**：
1. 「命中 0 人」是最危险的信号，因为**它不报错**。任何派生判据第一次上线都必须先报一个占比。
2. 「有系数没输入」「有开关没路径」是同一个 bug 的两种形态。登记表专门列了「未接线输入」，
   并把它们的**最大可能影响**算出来（`warningInformation` 若全部取 1，动员只快 exp(0.147)≈1.16 倍），
   这样报告里可以说「这条没接，但影响上界有数」。
3. 断言要贴实际写法。案例③的测试第一版写成 `/c\.hasCar && c\.license/`，与实际
   `if (!c.hasCar || !c.license)` 反向，导致 1 FAIL——测试本身也会「看着对、实际不检查」。

## 四、这套机制改变了哪些数字（不是纯文档工作）

可审计不是事后写说明书，它在过程中改掉了三个真数字：

1. **同伴乘车从 0 变成真实统计**：300 人 u_p120 工况下 6 档网络对比，零同伴档
   14.7%→2.5%，中间档 9.3%→26.0%——「同伴全走光」这种失真读数被压掉。
2. **照护责任从恒不触发变成 1.21% 人群**（8,256/681,294 加权），门5 从两条变三条，
   新增姿态 `gather_child`（且危险到 most 自动解除，不会永久锁死）。
3. **车队绑定从「人人可能有车」变成「只有有车有驾照的人」**，驾驶请求在 1000 人
   工况下仍然是 5,879（说明真实有车户足够多），但个案层面的「无车户开车」消失。

这三处的共同点：**修复前都表现为「模型能跑、测试全绿、数字漂亮」**。

## 六、和领域做法对齐（这一节决定它算不算方法学贡献）

「可审计」如果只是「我们 документ 写得好」，审稿人会归到工程实践。要站住，得说清
它对应领域里哪几个既有要求，以及本项目多做了什么。

| 领域既有要求 | 出处 | 本项目对应物 | 本项目多做了什么 |
|---|---|---|---|
| 模型描述要能被人复现：目的、实体、调度、子模型 | ODD 协议，Grimm 等 2006 *Ecol. Model.* 198:115–126；2010 同刊 221:2760–2768 | `项目总览.md` 的结构（人群/网络/决策/伤亡/驾驶/渲染分层）+ `docs/口径表` | ODD 是**描述**协议，不管数字对不对；本项目把 61 条常数逐条标性质（真实/实测/推导/自设/工程）与出处，机检 648 项 |
| 用多个不同层面的实测模式同时约束，而不是调参数凑一个结果 | 多模式建模 POM，Grimm 等 2005 *Science* 310(5750):987–991, DOI 10.1126/science.1116681 | 人群六维分布（总变差 0.009–0.031）、决策方向、死因结构、撤离时点曲线 | POM 通常要求「模式」来自独立观测；本项目目前只有人群分布是外部锚定的，其余是内部一致性 + 文献方向。**这是缺口，不能吹** |
| 校核（verification）与验证（validation）分开 | 领域通识；Windrum 等 2007 *JASSS* 10(2):8 把「样本内复现」与「样本外预测」分开 | 校核层：内核闭合差、质量守恒、绊线、回归测试；验证层：DC311 706 点命中（2.1%，CSI 0.017） | 本项目校核层做得比常见 ABM 细（闭合差 ≤0.0004%、61 条常数机检）；验证层很弱，必须明说 |
| 随机模型要给输出不确定性与统计推断 | Hartig 等 2011 *Ecol. Lett.* 14:816–827；Lee 等 2015 *JASSS* 18(4):4 | 单 seed → 计划 3 seed × 4 工况；敏感性（暴露时长/网络/四开关/增水三点） | 目前只有敏感性扫描，**没有正式的置信区间**——这是下一轮必做 |

**可以主张的**：把「数字可核对」从文档要求变成可执行机制（登记表 + 机检 + 绊线 + 抓错记录），
并且这套机制在过程中真的抓到了 4 类「能跑但结论是假的」错误（见第三节），其中第 ④ 类
（`exit 0` 但指标全 0）靠任何单一手段都抓不住，必须「结果自证 + 比较器拒绝 + 测试钉死」三件套。

**不能主张的**：这套机制保证不了模型正确。它只保证「你现在看到的每个数字，都能追到
一行代码或一篇文献；改任何一处，机检会红」。外部验证仍然只有 DC311 那 15/706 点。

## 六、学术定位与局限（别把可审计说成正确性）

- **能主张的**：这套工程把「参数依据」从叙述变成了可机检的资产；同类「接线不生效」的
  错误在本项目被机制化地抓出三次，而不是靠人记得。这对 ABM 的可复现性讨论是实打实的贡献。
- **不能主张的**：可审计 ≠ 正确。出处齐全只说明「没编数字」，不说明「模型对」。
  外部验证依旧是硬伤（DC311 706 点里只有 15 点落在官方内涝，CSI 0.017）。
- **审稿人会问的**：「这不就是工程卫生？」回答要落在**可检验的后果**上：这三类错误
  在常规 ABM 里会静默存在，而它们直接改变同伴效应、照护门、车辆可行集三个行为通道。
  最好再补一个「故意注入错误 → 机检是否红」的对照实验（待做）。

## 七、ODD 对照（审稿人会拿这个问「描述够不够」）

ODD（Grimm 等 2006／2010）要求的七块，本项目各自的落点。**没落点的就写没落点**，
比硬凑更安全。

| ODD 要素 | 本项目落点 | 备注 |
|---|---|---|
| 目的 Purpose | `docs/论文骨架_2026-11-22.md` 的「一句话贡献」+ 十条 claim | 目的写窄（方法学），不写「预测某次洪水」 |
| 实体、状态变量、尺度 Entities | `web/src/kernel/population.js`（ACS 逐人抽样）+ `peer-network.js`（户/同事/邻里/长程四类关系） | 尺度：1000 人、DC 核心区、1 仿真秒步长、45 分钟一帧水情 |
| 过程概览与调度 Process | `web/src/kernel/choice-model.js` 五道门 + `web/src/live-agent.js` 每帧判一次 | 调度是「帧驱动 + 逐人概率」，非事件驱动队列 |
| 设计概念 Design concepts | 门结构（跨数据集 λ 不可估）、阈值级联（Rufat 2024 拟合）、可行集（门5） | 这一块是论文正文的事，不是文档的事 |
| 初始化 Initialization | `data/real/acs_dc.json` PWGTP 加权逐人抽；`seed` 决定抽样与网络 | 同一 seed 完全可复现；换 seed = 换一批人 |
| 输入数据 Input | `web/assets/flood/unified*`（DHI/FD2321 水深帧）+ `unified_index.json` | 水情是离线算好的，仿真不反算水 |
| 子模型 Submodels | 决策（choice-model）、伤亡（thresholds/incidents）、驾驶（traffic/drive-layer）、渲染（render/*） | 每个子模型都有独立测试 |

**ODD 里本项目明确没做到的**：① 没有正式的「模型目的 → 所需精度」论证（ODD 第二阶段要求）；
② 子模型之间的耦合没有单列文档（例如「水深帧 → 步速 → 暴露时长 → 死亡」这条链只散在代码与
`docs/个体归因` 里）；③ 没有第三方按 ODD 重建过。
