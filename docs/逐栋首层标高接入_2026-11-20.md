# 逐栋首层标高接入运行时（2026-11-20）

## 一、改之前错在哪

`web/src/kernel/floors.js` 里首层高只有一个常数：

```js
SELF_SET.foundationHeightM = 0.457   // DC 旧规 20 DCMR §3105.2：BFE 以上 1.5 ft
```

它被 `floorElevationM()`（floors.js:185-195）与 `assignFloor()`（旧 :244）无条件使用，
于是**全城 21,943 栋楼的一层地板都在同一个高度**。

这条常数的出处只管**洪泛区内的新建与实质改造**，而模型把它套给了全城每一栋楼 ——
包括没有抬高的老排屋、包括本来就架空 1 m 的商业楼。`docs/首层标高校正_2026-11-18.md`
算过这个误差有多大：同一场水，按统一 0.457 / 截断 1.20 / 逐栋分位数校正三种口径，
一楼进水的栋数分别是 **163 / 540 / 3358**。

Python 侧早就把逐栋值算好了（`data/derived/building_foundation_fema.json`），
但**JS 从来没加载过它**：数据在磁盘上躺着，运行时还在用常数。

## 二、这次接了什么（5 处，不新增假设）

| 文件 | 改动 |
| --- | --- |
| `web/src/kernel/floors.js` | 新增 `setFoundationTable()/foundationReady()/foundationMFor(id)`；`assignFloor()` 用**逐栋**首层高，返回值带 `foundationM / foundationSource / foundationScenario` |
| `web/src/terrain.js` | `loadBuildings()` 末尾调用 `loadFoundationTable()`，把 `foundation_fema.json` 解码成 `Map<id, m>` 注册进 kernel |
| `web/src/crowd-life.js` | 分楼层时传 `id: best.id`；把 `p.homeFoundationM` 记在本人身上；`out` 里带 `foundationM` |
| `web/src/ped.js` | `INC.tick` 的上下文加 `foundationM`（只在「在家」时给） |
| `web/src/incidents.js` | `floodFloor()` 与 `floorElevationM()` 改用 `ctx.foundationM`；缺值时回退全城 0.457 m（给 `undefined`，**不是 0** —— 给 0 等于把首层压到地坪，比原来更错） |

数据文件：`web/assets/city/foundation_fema.json`（294 KB，由 `tools/export_web_foundation.py` 生成）。
格式是「`codes` 四档 + 每个假说一条数字串」，21,147 栋命中、796 栋缺（缺的回退 0.457 m）。

## 三、默认用哪一组假设（这是假设，不是实测）

三组的基础类型占比是**假设**：

| 假说 | 平板 0.30 m | 填土 0.70 m | 架空 1.07 m | 地下室 1.22 m |
| --- | --- | --- | --- | --- |
| A_全国河岸 | 57% | — | 38% | 5% |
| **B_老城排屋（默认）** | **40%** | **5%** | **25%** | **30%** |
| C_商业为主 | 75% | — | 15% | 10% |

默认取 B：DC 的建筑存量以**带地下室的排屋**为主，A 是全国河岸样本（架空为主、
地下室只 5%），C 是商业区。三组都只改「占比」，不改 FEMA 2015 的四种规范台基值。

换假说做敏感性：`http://127.0.0.1:8140/index.html?found=A_全国河岸`（或 `C_商业为主`）。
**不同假说跑出来的数不能混报**，和两族雨型不能横比是同一条纪律。

## 五、方向性影响（不预先当结论）

首层高变高 → 室内一层进水变浅 → 「顶层被淹、楼内无路可退」这条路变少；
但地下室那条路（`BASEMENT.depthM = 2.2 m` 埋深）**不受首层高影响**，所以
「进地下室淹死」的比例会相对上升。**具体数字要等整族重跑，不能先写结论。**

## 六、遗留

- 首层高只接了「在家」。工作场所没有逐栋层数、也没有逐栋首层高（`crowd-life.js`
  对 work 不传 totalFloors，这是旧设计：避免把办公楼按住宅层数误判）。
  所以**上班时段的室内淹死只按「室内即受保护」算，不判楼层** —— 这是下一层缺口，
  不是这次能顺手补的（需要 workplace 层数与面积，得另做数据）。
- 796 栋缺值全部回退 0.457 m，占 3.6%。回退比例每次报表都会给出，不算隐藏项。
- `docs/首层标高接入_2026-11-18.md` 里那套「MIN_Z 中位 1.86 m / 截断 1.2 m」的方案已废止，
  这次用的是 FEMA 分位数校正值，不是 DCGIS MIN_Z。
