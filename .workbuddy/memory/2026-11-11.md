# 2026-11-11 工作日志

## 决策模型重做：从「拖时间轴摆拍」到「连续仿真的一天」

用户核心质疑：拖到某分钟弹出的那段话是预写好的，不是真决策；决策间隔 20~25 分钟太蠢；
应按职业/年龄/社会地位分群体写判断内核；人每天有目标节点（上班/吃饭/回家），在
实现目标的过程中做决策（含放弃）；演示只保留现在「点名跟拍一个人」的效果。
补充澄清：0.5~1 秒不是重定目标，是「当前状态下现在该干什么」；倍率下判断/动作/
积水必须同时间层；人数加到约 1000；验收单独写程序、后期找空闲再跑。

### 落地（阶段 0–6 全部完成）
- `clock.js`：新增 `beginFrame/stepTo/endFrame`，一帧 simSec 拆 ≤0.2 仿真秒子步
  （最多 12 步）；`advance()` 保留兼容。`main.js` 主循环改子步循环：每子步
  时钟→故事/具名角色/车→行人判断与位移→水深采样→流场回写；零 dt 走一次空步
  兼容 `__frame(0,2)`；`__frame(dt,n,skipRender)` 支持验收跳过渲染。
- `goal.js`（新）：9 个目标节点（休息/上班/午饭/下班/办事/回家/睡觉），时间窗+
  真实门牌，状态 pending/active/done/abandoned/timeout；走到门牌才算完成，
  home/sleep 不判超时（记「休息够了」）；`reset(minute)` 对齐拖轴。
- `cohort.js`（新）：职业→社会地位（白领/专业人士/服务业/蓝领/零工/学生/退休）
  ×年龄×经验的判断内核（涉水线/绕远意愿/耐心/从众/紧迫度/放弃阈值/噪声温度），
  `judge()` 用威胁门控 + 分层候选池 + softmax 采样；平静时只在继续/放慢/加快里挑，
  有状况才开放换街/掉头/等待/放弃；reason 由当前状态现算。
- `live-agent.js`（新）：每 0.5~1 仿真秒一次判断（实测 1.3 次/人/秒），O(1) 感知；
  换街/改道才调 A* 且每仿真秒全局预算限流；决策冷却（放弃 90s、换街 12s、等 6s）；
  目标 pendingGoal 错峰规划；`applySocial` 统一接管社会状态；`reset()` 重建随机序列
  保证同种子可复现；事件日志（非 continue）供验收。
- `ped.js`：接入 LIVE（`stepOne/applyLiveAction/planToGoal`），动作落到真实路网折线、
  步速、等待、放弃；`CROWD.setLiveOverride` 让社会层/行人层/HUD 读同一份状态；
  等待时 `updateRoute` 直接 return（不播走跑、不计零位移帧）；帧末 6cm 阈值单帧兜底。
- `crowd-life.js`：`at()` 增加 override 钩子与 `streetSceneId`；`DEST_CAP` 动态
  `max(8, ceil(count/42))`（1000 人时 24，避免 24/8 超限）。
- `main.js`：默认 1000 人；HUD 详情面板加实时目标/群体/最近判断；`FLOOD.rainRate`
  沿用；决策流空状态文案改掉「拖时间轴」。
- `_sim_day.mjs`（新，**只写不跑**）：连续播放不 seek、按倍率跑满 24h、跳过渲染、
  每批取走事件流式聚合，出 `out/sim_day.json`（动作分布/目标结果/群体差异/
  无依据改道/积水同层/脚本错误）。用法 `node _sim_day.mjs [分钟=1440] [倍率=48] [人数=1000] [输出]`。

### 迭代抓到并修掉的问题（6 轮）
1. 平静状态 73% 判断是乱改道/放弃 → 威胁门控 + 分层候选池 + 噪声缩放，降到 ~5%。
2. 放弃后 `forceActivate` 把 17:00 的目标在早上激活 → 连环假超时 1017 次 →
   只激活「现在该办」的目标 + `forceActivate` 禁止复活已结束目标。
3. 拖轴后目标状态不回退 → `LIVE.reset(m)` 由 `CLOCK.onSeek` 调用，且重建随机序列。
4. 1000 人同时 A* 挤爆（budgetBlocked 6623）→ 初始 planDelay 错峰、室内不可见人
   不跑 mixer、规划预算按仿真秒限流（降到 892）。
5. 社会层说室内、行人层在走（室内走跑 376）→ override 移进 `at()` 内部，
   并同步换 `sceneId` 为街段场景（时间轴 104078 条错配 → 0）。
6. 等待/重规划出现零星原地跑 + 零位移帧 5127 → 等待时不推进不计帧、折线走完
   那一帧不算零位移、单帧静止即切 idle（playwalk PASS、routes 零位移帧 0~1）。

### 验收
- 倍率同步：×1 vs ×24，分钟 23.95×、仿真秒 24×、`FLOOD.tMin === CLOCK.minute`，零错误。
- 连续播放实测（不 seek）：早高峰 continue 95%、目标完成/激活各 125 次；暴雨窗口
  wait/detour/turnback/abandon 显著上升（环境真的驱动决策），冷却后放弃降到 0.5 次/人/3min。
- 回归全绿：`_check_citizens` 19/19、`_check_routes` 17/17、`_check_playwalk` PASS、
  `_check_actions` 0 FAIL、`_check_carclip` PASS、`_audit_timeline` 190 点 0 错配。
- 1000 人性能：无头 SwiftShader 约 222ms/帧（240 人约 260ms/帧，说明瓶颈是软件渲染
  不是人数，真实 GPU 浏览器会快很多）；页面零脚本错误。
- `_sim_day.mjs` 只做 2 分钟 / 60 人烟测（11.6s，零错误，同层 true），**正式 24h 未跑**。

### 口径更新（旧验收脚本）
`_check_routes` 的 steady/shortcut 断言改为「本段有路线启动 + 有人在走」；
`_check_citizens` 的 enterWalk 位移断言改为「可见人真实移动人次」。均为模型更替后的
诚实对齐，不是放水。

### 遗留
- 正式 24h 连续验收程序后期找空闲时间跑，预计 ×48 / 1000 人约 20~40 分钟。
- 高倍率（×48）子步 h=0.2，远处人判断仍是全频率，需实机看 CPU。
- 旧 Brain 的预写候选与作息表仍作为「时间窗/门牌资源」存在，但不再产出决策文案。

## 第二轮修正（用户反馈：一开就 18 点 / 0 点满街 / 马克公寓挤满 / 太集中 / 两套系统）
### 根因
1. `main.js` 写死 `CLOCK.minute=1020`，马克时间轴范围也只给 1072–1115。
2. 实时 `applySocial` 把“在家休息/睡觉”的 active 目标也强制标成 street，
   0 点 502 人站街；且 rest 目标受 ±20 分钟 jitter 影响，一半人无目标。
3. 1000 人共用 9 个 `sc_home_*`，全塞进马克公寓；住宅门牌仍是 42 个抽象点。
4. 马克/6 个具名角色仍由 `DAYMOTION`/`OfficeStory` 驱动，与 PED 是两套位置。
5. 目标推进允许过期节点“补激活”（45 分钟宽限），21:40 被拉起补 17:10 的班。
6. 判断“到家”用当前坐标到门口距离，人进房间后下一帧又判没到，场景来回翻。
7. 高倍率 `steps` 封顶 12 后单步可能 >0.2 s，倍率越高物理粒度越粗。

### 修复
- 默认 00:00；马克时间轴滑块改 0–1440；`?markt=0` 可显式指定。
- 新增 `crowd-life.bindResidents(peds, SOLIDS)`：按出生片区就近绑定全城真实建筑
  住宅，单栋上限 6 人；普通岗位也就近匹配（≥180 m），不再全去 FAA。
- 普通住宅 `residence_*`、岗位 `office_*` 不再借精细室内模型；马克独占 565 Penn。
- `goal.js` 目标按 id 取自己的家/岗位/餐馆门牌；home/work 到达后持续到时间窗结束；
  过期节点不再补激活；节点改为 8:00 上班 / 12:00 午饭 / 17:00 下班。
- `applySocial` 只在 `arrivedAt` 或真实到门牌时标室内；工人/骑手到岗仍室外。
- `MARK.bindLive` / `PEOPLE.bindLive`：马克与 6 名角只同步第 0~6 个实时居民，
  旧 DAYMOTION 不再写位置；`_check_actions` 改为 6 个时刻同源比对。
- PED 室外高度硬约束：离地 >1.2 m 接回地面；室内不可见时先把脚底摆到房间锚点；
  马克跟拍屋内用 q 的房间锚点而不是楼门口代理位置。
- `clock.beginFrame`：子步 h 恒 ≤0.2 s，最多 60 步；超高倍率降频而不是拉长单步。

### 实测（1000 人 / 默认 00:00）
- 00:00：999 人在室内、0 人在街上、0 人悬空；住宅 **429 栋**，单栋最多 6 人，
  马克公寓非本人 **0**；7 个具名模型与实时居民误差 **0 m**。
- 全天 8 个关键点（0/200/415/600/720/1030/1080/1300）：离地 >1.2 m = 0，
  >3 m = 0，屋顶/半空 = 0；最大 1.1 m 为路缘铺装高差。
- 07:00：599 室外（后续 857 因通勤+户外岗位）分布在 231 个 120 m 网格，
  平均 2.6 人/格；最大 28 人（同岗位）。
- 连续 0→9:10（240 人，不 seek）：0–6 点全在家，6:55 开始出门，7 点 175 人在
  真实移动；动作事件有“被挡住等 0.8 s / 路滑放慢 / 掉头绕开”。
- 回归：citizens 19/19、routes 17/17、playwalk PASS、actions 0 FAIL、carclip PASS。
- 已知：`_audit_timeline.mjs` 仍在审旧 DAYMOTION 7 人剧本，对实时层的新口径
  会产生假阳性，正式验收应使用 `_sim_day.mjs`。
