
## MegaKit 真替换 + 可进入楼（2026-11-04 下午）
- 用户三连要求：① 3D 楼要能进出 ② 用他给的模型自己拼 ③ 把原来的纸壳子替换掉 ④ 让城市真的是城市。
- **真替换**：`buildBuildingMesh()` 早有 `opt.excludeIds`。先算 `MK_IDS`（半径 460 m，`?mkr=`），塞进 EXCLUDE，MegaKit 只建这个集合 → 不重叠不漏空。第一版是放大 1.5% 包在原楼外面，被指"纸壳子"，已废。
- **可进入**：临街面=footprint 最长边；中间跳一节墙开门洞（2×3 m）+ DoorFrame_Trim + Door_2/Door_1 双扇 + Entrance_Concrete_2x1 压 0.4 m 台阶 + 门厅（地面 3×0.4×depth / 左右后内墙 / 自发光天花）。门厅四件必须有，否则从门洞看穿到对面。
- **三个关键坑**：
  1. `Brick_Plain_3` 是 4 顶点单面片（厚度 0，0.2 是包围盒），法线朝 -Z → 按 X=-d/Y=up/Z=n 摆位后从街上看到背面被剔除，整面墙消失。修法：外墙材质全 DoubleSide。
  2. 屋顶黑：`material.color` 是乘数，黑贴图乘还是黑。必须换不带贴图的纯色材质。
  3. 坡顶逐栋三角化 21 栋全不可见（侧面法线水平，绕向修正判不出，被剔）。改用 `CylinderGeometry(0.34,0.707,1,4)` 当四棱台 + 实例缩放。
- 面数 40.0k → 22.0k/栋（LOD 三档按距离调 windowEvery + winFloors）。49 栋 1,078k 面 / 70 mesh / 109,464 实例 / 拼装 3.7 s。
- 调试开关：`?xray=Brick_Plain_3` 染色定位、`?nowin=1` 关窗、`?mkeye=1&mx&mz&tx&tz&mh&th` 手动机位、`?onlymk`（已废，真替换后不需要）。
- **遗留**：街上没人/没车/没信号灯；楼与路之间是草地（landcover 原样）；外墙每层一条深色横带 + 每 2 m 竖缝，近看重复感强。

## 「栅格板」修复（2026-11-04 晚）
- **根因**：墙按 2 m 分节拼，一栋 14 层楼 400+ 个盒子；UV 全 0-1 让 2 m 砖贴图压到 0.26 m 厚侧面；相邻盒浮点误差露缝 → 远看是一根根竖条。

## 侧墙整体转了 90°：左手系基矩阵（2026-11-04 晚，用户"侧墙的 x,y 方向错了"）
- **根因**（诊断 21943 栋 / 87772 条边）：数据 footprint 绕向导致**每一条**边的外法线都要从 `(dz,-dx)` 翻成 `(-dz,dx)`。旧代码翻了 Z 却把 X 写死 `(-dx,0,-dz)` → `makeBasis(X,UP,Z)` 是**左手系（det = -1，87772/87772 全中）**。
- `Quaternion.setFromRotationMatrix` 只接受纯旋转；对镜像矩阵解出退化四元数（normalize 后就是恒等旋转）。于是所有墙盒的局部轴被钉死在世界 X/Y/Z：沿 X 的边碰巧对，沿 Z 的边（**侧墙**）长边与厚度整整错 90°，等于没盖 —— 上一轮"转角咬合"根本救不了。
- **修**：右手系要求 `X × Y == Z`，即 `X = Y × Z = (nz, 0, -nx)`，任意绕向都成立。同步把门厅 `at()` 的 `Xv` 从 `-d` 改成 `(nz,0,-nx)`（否则门扇/门厅相对门框镜像），楼脚铺装带 `qy` 去掉多出来的 `+π/2`（长轴原本被转到法线方向，变成从楼里横穿出去的 L 米大板）。
- **验证**：1333 面墙的长轴 672 沿 X / 661 沿 Z（此前 1333 全沿 X），厚度恒 0.26，长轴与厚度轴 dot ≈ 0 全部正交；47 mesh / 286k 面不变。截图 `web/out/fixdir_eye.png`、`fixdir_corner.png`：街区两面墙都完整、转角相交正常。
- **教训**：`makeBasis` 后要检查 det；四元数不能吃镜像矩阵。诊断别只看实例缩放对不对（badScale=0 完全没暴露问题），要看**基向量的方向**。
